## Проверка до расчета метрик

- Оба каталога должны содержать ровно `fold_1_7.npz` … `fold_6_12.npz`; лишние NPZ и пропуски отклоняются.
- ID уникальны внутри каждого файла и между всеми фолдами. Полное объединение ID каждого каталога должно точно совпасть с `split=train` в features.
- Поддерживаются ID в целочисленном dtype и legacy float ID, если значения конечны, точно целые и по модулю не превышают `2**53`. Дробные и небезопасные float ID отклоняются. Нормализация сохраняет идентичность ID.
- Множества ID каждого соответствующего фолда совпадают; порядок строк может отличаться. После выравнивания y совпадает между файлами **и** с обязательным `TAXITIME_SEC_mvt` в features. Два файла с одинаковыми неверными y также отклоняются.
- Месяц берется из features (`month`, иначе месяц `MVT_TIME_UTC_mvt`). Каждая строка принадлежит своему месячному фолду. Если NPZ содержит `month`, он обязан совпасть с features после выравнивания. Legacy NPZ без месяца поддерживается без изменения исходных файлов.
- `pred/y`, а также присутствующие `reg/proba`, конечны и имеют ожидаемые формы. `proba/values`: `(N, 6)`. `values` допускает NaN в плановых кандидатах, как действующая математика смеси; бесконечности отклоняются. Поврежденные NPZ, object arrays/pickle, отсутствующие поля, дубли имен массивов и неверные формы отклоняются.
- Любой сбой/переполнение при вычислении SSE означает invalid. Импорты ограничены стандартной библиотекой, NumPy и Polars; training-модули не импортируются.

## Метрики и выходы

Точные legacy decided/strict маски, порог body `y <= 7200`, trimmed с удалением трех крайних SSE-дельт с каждой стороны **в каждом фолде**, и нормализация `6 * 2 * 252.43 * 344841`. Суммы в float64.

Принятие требует global decided `< 0`, не менее 4/6 улучшенных decided-фолдов и trimmed `< 0`. `--require-body` дополнительно требует body `< 0`. `--audit-only` проверяет/измеряет даже одинаковые control/candidate, сохраняя фактическое состояние `gate_passed`.

Коды выхода:

- `0`: accepted либо audit_valid.
- `1`: валидный эксперимент отклонен гейтом.
- `2`: malformed/incomplete input либо ошибка сохранения JSON.

JSON содержит суммы SSE, нормализованные метрики, каждый фолд, число строк, gate flags, пути и параметры нормализации. `--json -` выводит только JSON; `--json PATH` создает новый файл без перезаписи существующего. Даже ошибочный путь к исходному NPZ не может его перезаписать.

`--check-values` — отдельная диагностика regular/day кандидатов относительно reg и reg+86400, с абсолютным допуском `1e-6 s`. Stale values сообщаются, но не превращают валидный сохраненный pred в invalid.

## TDD и проверка

До реализации: 28 синтетических тестов завершились FAIL с ожидаемым отсутствием самостоятельного gate. При первом green-проходе исправлены две ошибки фикстуры Polars (литерал Int32 вместо Int64 при concat); production-проверки не ослаблялись.

Второй red/green цикл проверил две реальные дополнительные защиты: duplicate NPZ array names раньше не отклонялись, JSON раньше мог перезаписать исходный NPZ. Оба теста показали FAIL; после исправлений прошли.

Команда собственных тестов:

```sh
OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 POLARS_MAX_THREADS=2 \
  .venv/bin/python -m unittest discover -s tests -p test_strict_oof_gate.py
```

Результат: **30 tests, OK**, 0.515 s.

Общий доступный набор на момент проверки: та же команда с `-m unittest discover -s tests` → **55 tests, OK**, 1.461 s. Остальные агенты могут позднее расширить этот набор.

Дополнительно на 48-строчной синтетической шестифолдовой фикстуре результат сравнен непосредственно с неизмененным `fold_metrics.compare`: весь tuple `(decided, all, body, trimmed, lower, n, strict)` совпал точно. Hand-computed SSE: decided −684, strict −570, all −912, body −798, trimmed −228; lower 6/6.
