# Проект пред-регистрации №270: фиксированный E185 поверх принятого E182

Этот текст и `src/e185_on_e182_fixed.py` предназначены для регистрации одним
коммитом **до первого запуска на реальных OOF**. Общий журнал не изменён.
Синтетические тесты не оценивают эффект на данных соревнования.

## Гипотеза и неизменный рецепт

Уже обученный член E185 «только движения» сохраняет добавочную пользу после
замены пяти LGB-якорей на принятый E182. Контроль — именно сохранённый кандидат
`data/cv_preds_e172_rawf_lobtf_schedf_eobtf_aobtf_mlpa_f1b`, а не FIN1b без членов
и не прежний контроль E185. Член — `data/cv_e130motion`.

Вес **0.35 во всех шести фолдах**. Ни новой сетки, ни LOFO-подбора этого веса,
ни обучения, ни выбора подмножеств после просмотра исхода. Маска прежняя:
`LOBT_flt IS NULL AND ADEP_mvt != "LIRF"`. Для ranking остаётся
`0.35 * 2 / 3 = 0.2333333333333333`; этот runner ranking не собирает.

Вес .35 был выбран на более раннем CV E185 (№260), использующем эти же OOF.
Это зарегистрированная проверка добавочности с фиксированным ранее выбранным
весом; **не новая независимая внешняя валидация**. Проверяется смесь до ADS-B,
а не точная полная цепочка финального сабмита. Сильный результат доски №267
не используется для изменения веса или выбора другой сетки.

**Предлагаемый прогноз, ещё не измеренный:** decided −0.03 с, коридор
[−0.10; +0.04]; trimmed −0.02 [−0.08; +0.04]; body(y≤7200) −0.03
[−0.10; +0.04], улучшение в 4–5/6. Это ожидание частично сохранившегося эффекта
исходного E185, а не результат расчёта комбинации. Прогноз доски новой полной
цепочки следует отдельно зарегистрировать перед её сборкой/отправкой.

## Гейт без добавления условий

В №255 написано: «decided ≥4/6, усечённые <0, y≤7200 <0». Там нет отдельного
требования суммарного decided<0. Применяем буквально прежние три условия
**относительно принятого E182**:

- decided SSE меньше контроля в ≥4/6 фолдов;
- trimmed SSE delta <0 (прежний gate: по три крайние разницы SSE с каждого
  конца в каждом полном фолде);
- body SSE delta для y≤7200 <0.

Суммарный decided, all и strict публикуются как диагностики. Runner использует
валидацию/расчёт `strict_oof_gate`, но заменяет его более строгий общий вердикт
точным исходным гейтом №255. `--audit-only` исходного инструмента также считает
метрики; до регистрации его запускать нельзя.

## Проверка происхождения и сохранение прежних поправок

До расчёта исходов обязательны все шесть фолдов `fold_1_7`…`fold_6_12`,
уникальные точные целые ID, полное покрытие train, соответствие пар месяцев,
одинаковые y у FIN1b/контроля и принятых E182, finite reg/pred/члены/вероятности,
точное соответствие ID каждого члена. Источник y — `features_fin1b.parquet`.
Сверяются исходные `features_e106.parquet`: поля маски/LOBT, метки, месяцы и
популяции прежнего гейта. Любое расхождение означает invalid, не переход на
другой рецепт. Нельзя исправлять реальные артефакты по исходу этого теста.

Принятый E182 восстанавливается из `data/cv_preds_fin1b_hz`, всех 36 текущих
member-fold файлов и **сохранённых весов фолдов**, а не pooled optimum:

| Фолд | rawf | lobtf | schedf | eobtf | aobtf | mlpa |
|---|---:|---:|---:|---:|---:|---:|
| 1+7 | .05 | .15 | .15 | .10 | .15 | .30 |
| 2+8 | .10 | .20 | .10 | .15 | .15 | .20 |
| 3+9, 4+10, 5+11, 6+12 | 0 | .15 | .15 | .15 | .15 | .30 |

Записи сверяются с `data/e182_grid_5f.log`; восстановление reg и pred должно
совпасть с принятым E182 с абсолютным допуском 1e−6. Вероятности и средние
четыре столбца values должны совпасть с его FIN1b-базой.

Для каждого фолда и только на исходной маске S:

```python
reg_new[S] = .65 * reg_e182[S] + .35 * motion[S]
pred_new[S] = pred_e182[S] + mix(reg_new)[S] - mix(reg_e182)[S]
```

`mix`: float64, замена крайних столбцов values на reg и reg+86400,
прежние вероятности, NaN планов→0, прежнее окно LOBT ±3606, clip снизу нулём.
Сохраняется `pred−mix(reg)`; нельзя заменить готовый pred на одну новую смесь.
Вне S значения reg/pred неизменны. У новых кандидата и копии контроля values
синхронизированы в float64; pred/reg копии контроля остаются исходными.
Проверка согласованности values обязательна, а не диагностическая.

## Воспроизводимость и запуск после регистрации

Runner требует SHA коммита регистрации и свежий выходной каталог; отказывается
перезаписывать существующий. Файлы сначала создаются в соседнем временном
каталоге. Только после всех проверок, измерения и повторной проверки входных
хешей публикуется весь каталог. Обрабатываемый invalid не оставляет итогового
каталога; после жёсткого завершения может остаться скрытый `.partial-*`, который
не считается готовым результатом. Resume отсутствует; повтор требует нового
каталога. Поля исходных NPZ не перезаписываются, исходники не меняются.

`manifest.json` записывает SHA256 источников, фактически исполняемого кода,
двух feature-таблиц, 54 исходных NPZ, журнала весов, выходов и регистрационный
коммит; `verdict.json` — метрики и буквальный гейт №255. Контроль и кандидат
находятся в подкаталогах `control/` и `candidate/`. По два вычислительных потока.

Команда **только после коммита** кода и записи №270 (заменить SHA):

```sh
.venv/bin/python src/e185_on_e182_fixed.py \
  --repo-root . \
  --output data/e185_on_e182_w035_20261005 \
  --registration FULL_PREREGISTRATION_COMMIT_SHA
```

Коды выхода: 0 — исходный гейт пройден, 1 — валидный эксперимент не прошёл,
2 — invalid/ошибка исполнения. При провале вес не изменять; зарегистрировать
вердикт отдельной записью. Сборка/подача комбинации требует отдельной проверки
полной ranking-цепочки.

Синтетическая проверка, допустимая до регистрации:

```sh
.venv/bin/python -m unittest discover -s tests -p test_e185_on_e182_fixed.py -q
```
