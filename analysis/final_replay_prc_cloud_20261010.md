## 2. Почему расходится E156: разный числовой стек

Версии пакетов одинаковы: numpy 2.5.3, polars 1.44.2, lightgbm 4.7.0, tabpfn 8.5.0, pandas 3.0.5, sklearn 1.9.1,
scipy 1.18.1, pyarrow 25.0.1, torch собран из одного коммита 08187d9e (`cloud/versions.txt`). Различаются числовые
библиотеки под ними (`cloud/numeric_backends.txt`):

| | Мак (macOS 27, arm64) | prc-cloud (Linux 7.0, Neoverse-N1, glibc 2.43) |
|---|---|---|
| BLAS/LAPACK numpy | Apple Accelerate | scipy-openblas 0.3.34 (DYNAMIC_ARCH) |
| BLAS torch | `BLAS_INFO=accelerate` | `BLAS_INFO=nvpl`, oneDNN доступен (torch 2.14.0+cu130) |
| OpenMP | libomp | libgomp |
| libm | Apple libm | glibc |

Данные на входе TabPFN одинаковы. Значит, разница возникает внутри препроцессинга или инференса TabPFN, на операциях
BLAS/LAPACK/libm. Ошибки в коде или в данных здесь нет. Я не выяснял, какая именно операция раздувает разницу до 1e−2:
кандидаты — разложения в препроцессинге ансамбля или порядок накопления в матричных умножениях. Для этого нужны
дополнительные прогоны TabPFN, а они вне задачи. Это гипотеза, не измерение. LightGBM premix расходится только на 1 ulp
и согласуется с разными `exp` в softmax (glibc против Apple libm). Округление это поглощает.

**Следствие.** Побайтно повторить финал на prc-cloud нельзя даже при совпадающей строке интерпретатора. 62 строки E156
восстанавливаются из выхода E156 на стадии `protect` и доходят до финала без изменений: в файле мака все 62 значения равны
served-значениям. Ниже прогноз, а не измерение. Если бы стадии 4–11 повторились точно, финал prc-cloud отличался бы ровно
в 55 строках. RMS разницы по всему файлу была бы √(10 939 / 670 790) = **0,128 с**. По неравенству треугольника
\|ΔRMSE\| ≤ 0,128 с; на деле, скорее всего, на порядки меньше.

Побайтная воспроизводимость финала **привязана к платформе.** На маке (macOS arm64 + Accelerate) пересборка дала тот же SHA
(№438). На prc-cloud повтор детерминирован внутри машины: run0 = run1. Между платформами premix/E185/E167 совпадают по
значениям, а на входе первой обучающей стадии E141 совпадают побайтно `data`/`label`/`weight`. Зависит от платформы только
хвост E156 (55 из 62 строк LIRF, ≤ 35 с).
