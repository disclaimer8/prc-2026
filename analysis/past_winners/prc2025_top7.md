Итог считается по файлу `<team>_final.parquet` на объединении сентябрь+октябрь (61 745 строк). Колонка «Oct» ниже — моя обратная выкладка из Sep и Sep+Oct через взвешивание по строкам. **Расхождения источников:**

## 3. Приёмы для taxi-out (8–12 пунктов)

1. **Фильтр физической правдоподобности только на train, отдельно по каждому хвосту.**
   - Источник: RQ, 0.05–6.5 кг/с, 228 → 205 (отчёт, табл. 3; нижняя граница слегка вредила); JV `data_utils.py:73-86`; HR `13_prune_outliers.py`.
   - Для нас: taxi-out ≤0, выше разумного потолка, неправдоподобная средняя скорость (путь стоянка→ВПП / время). Потолки считать по аэропорту. Test не трогать. Каждый хвост проверять отдельно.
   - Польза высокая, сложность низкая.
2. **Таргет как «темп» относительно базы, прогноз × база.**
   - Источник: RQ кг/с против кг, 199.91 против ~220 (табл. 4); MJ, ZM, HR.
   - Для нас: отношение к медиане taxi-out по связке аэропорт×ВПП×стоянка (или секунды на метр пути). Обязательно сравнить с сырыми секундами, потому что 2-е место учило сырые кг, и с `sample_weight ∝ база²`: RMSE считается в секундах.
   - Польза средняя или высокая, сложность низкая.
3. **Стабильный простой априор как признак лучше шумной выученной подмодели.**
   - Источник: RQ, эвристическая масса 199.91 против рекурсивной 203.09 (табл. 4); OT, прогноз OpenAP как признак хуже (237.67 против 227.23, README:144).
   - Для нас: исторические медианы и квантили taxi-out по аэропорту×ВПП×стоянке×часу, строго из прошлого периода или out-of-fold. Смещение по группе считать тоже out-of-fold, потому что у JV оно течёт (`feature_engineering.py:1080-1128`).
   - Польза высокая, сложность низкая.
4. **Валидация walk-forward по времени, число деревьев = p75 от best_iteration.**
   - Источник: ZM, яч.25, 30, 54, 65; статья организаторов §5.1 о перетасовке рейтинга сентябрь/октябрь.
   - Для нас: блоки по месяцам 2025, early stopping на блоке k, оценка на k+1, отдельная оценка на месяцах, похожих на январь и июль. Разброс фолдов важнее среднего: у RQ фолды были от 136 до 290.
   - Польза высокая (главный риск — сдвиг между годами), сложность средняя.
5. **Групповая изоляция и отдельный early stopping.**
   - Источник: OT, 160 проб Optuna с утечкой → 303.5 против 227 (README:152); HR `V9:322`; UH яч.69; MJ `break`.
   - Для нас: фолды по дате или дню (движения одного дня коррелированы через загруженность). Early stopping на отдельном внутреннем блоке, не на оценочном. Пройти все фолды.
   - Польза высокая, сложность низкая.
6. **Скор для подбора: mean + 0.5·worst по нескольким схемам CV.**
   - Источник: HR `PRC2025_V9.py:301-316,450-453`.
   - Для нас: схемы «период целиком», «аэропорт целиком», «бакет загрузки». Защищает от провала на одном аэропорту или сезоне.
   - Польза средняя, сложность низкая.
7. **Huber как альтернатива удалению выбросов.**
   - Источник: ZM `objective='huber'` (яч.39, 48).
   - δ подбирать в секундах: дефолт LightGBM 0.9 рассчитан на кг/с. Сравнивать с L2 + фильтром на временном holdout. При RMSE L2 на очищенном таргете может выиграть.
   - Польза средняя, сложность низкая.
8. **NaN плюс флаг «нет данных» вместо импутации.**
   - Источник: OT GeoInfo 235.63 → 227.33 (README:149-150); RQ `fill_gap` ухудшал (отчёт стр. 107-114); MJ `is_missing_data`.
   - Для нас: отсутствующие EOBT/IOBT/LOBT, пропуск стоянки или ВПП. Не заполнять средним до GBDT.
   - Польза средняя, сложность низкая.
9. **Клиппинг прогноза по группе.**
   - Источник: OT `post_cleaning/MaximumFuelSec.py:26-40`, [0; 1.1 × max по типу]; holdout 204.27 → 202.87, общий жёсткий потолок хуже.
   - Для нас: границы по аэропорту и ВПП, коэффициент подбирать на временном holdout.
   - Польза малая или средняя, сложность низкая.
10. **Выпуклый бленд разнородных моделей по OOF, включая модель на сыром и на нормированном таргете.**
    - Источник: JV Cat/LGB/XGB, CV 244.9 → 241.0 (`train_blend.py:86-100`, README:162-172); MJ 0.7·log-rate + 0.3·raw.
    - Бленд компенсирует смещение обратного преобразования. Веса ≥0 с суммой 1, только по честному OOF.
    - Польза малая или средняя (~1–2%), сложность низкая.
11. **Сверка категорий train/test и режимные модели.**
    - Источник: ZM, частоты типов (A20N 29% в train против 45% в rank, `aircraft_frequency.csv`), убраны типы, которых нет в тесте (яч.22), отдельные модели по полноте данных; UH, модели по фазам.
    - Для нас: таблица частот 2025 против 2026 по оператору, стоянке, ВПП и типу. Новые анонимные ID операторов в 2026 нужно обрабатывать через частотный или редкий бакет.

## 4. Ловушки, на которые жаловались или наткнулись участники

- **Шум меток от угадывания единиц.** FOB в ACARS без единиц (кг или фунты, ×10/100/1000), выбор по OpenAP с допуском 5–500%, авторы признают остаточные ошибки (статья организаторов §3.2, §5.2). Отсюда квантованный таргет: 45.3592 = 100 lb, 90.7184 = 200 lb, 200, 1200, 2500 (OT `evaluation_analysis` яч.40; UH Multi яч.13; ZM яч.11). У нас стоит проверить округление времени до минут.
- **Интервалы вне заявленных правил.** Заявлено 5–60 мин (§3.4), в данных минимум 1.6 с (OT `exploration.ipynb` яч.12), у RQ сегменты по 134 с. 1824 интервала заканчиваются до взлёта, 855 начинаются после посадки (там же).
- **Неточные границы интервалов** из-за задержки ACARS, неустранимо (§3.1.4).
- **`idx` в final-шаблоне начинается заново,** 24 289 дублей (MJ, ZM яч.100). Позиционная склейка рискованна (RQ `make_dataset.py:252`). У MJ сабмиты v12 и v29–v31 битые.
- **Публичный LB (сентябрь) плохо предсказывал приватный (октябрь):** §5.1, bright-lobster 213 → 349.
- **CV не совпадал с LB ни в какую сторону:** JV 241 против 224, ZM 162 против 221, UH holdout 216–223 против 235.
- **Утечки в CV:** случайный сплит по строкам при нескольких интервалах на рейс. На это указал рецензент bright-lobster (JOAS 9001, §3.1.5). Там же авторы выбрали конфиг по скрытому тесту.
- **Признаки и энкодеры, обученные на тесте отдельно** (UH яч.11, 38-50). Категории схлопывались отдельно в каждом файле (HR `17_aircraft_altitude_categoricals.py`).
- **Параметры, которые молча не работают:** `subsample` без `bagging_freq` (RQ); Optuna с `n_trials=1` по умолчанию (OT).
- **Погода ERA5 дорогая и бесполезная:** OT (4 ч данных = 180 с и 1 ГБ), JV (терабайты).
- **Документация расходится с данными по единицам:** статья, табл. 2 (м, м/с) против `data.html` и фактических данных (ft, kt).
