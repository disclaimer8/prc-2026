# Дневные очереди после перезагрузки Mac

Операционный протокол `PRC-postreboot-day-controllers-20261007-v1`.
Он не меняет научные рецепты и не повторяет model fits.

`scripts/prc_day_recovery_20261007.py` запускается один раз вне сетевой
песочницы Mac, в отдельной process session под caffeinate и с nice10.
Регистрация закрепляет этот файл, протокол и E201 collector. Каждый научный
controller дополнительно проверяет собственную прежнюю регистрацию.

Две независимые задачи начинаются сразу:

- E202: восстановление передачи по регистрации №354/5ef410c, сохранение
  неполных файлов, исходный admission, продолжение уже работающего GPU unit,
  сбор и независимая оценка. Новый GPU fit unit не создаётся.
- E201: сбор небольших проверенных пакетов, исходное распределение всех
  двенадцати donor-folds; Home берётся из memoryfix output. Коллектор не
  запускает и не перезапускает обучение. Новый state сохраняется отдельно.

E203 по регистрации №352/6e95e3a запускается только после завершения и аудита
Macfold2 по №353. Пока Mac выполняет этот тяжёлый fit, новый local pack/CV
не начинается. Проверяются SHA complete/audit receipts. Затем E203 сам
дожидается обоих компонентных гейтов E202 и своего current-chain gate;
лишь положительный результат разрешает ranking training и сборку кандидата.
Внешних загрузок этот controller не выполняет.

При сбое Macguard или транспорта до E203 его запуск отменяется с явной
записью причины. Остальные уже работающие узлы не останавливаются. Нет
автоматических повторов, изменений сред или выбора модели по частичному
результату. Все child PID, коды завершения и логи сохраняются в
`data/prc_day_recovery_20261007`; общий контроллер ограничен 18 часами,
дочерние очереди имеют собственные ограничения времени.

Это устойчивый запуск в рамках работающей ОС. Новая перезагрузка Mac
потребует проверки и явного восстановления передачи; удалённые systemd
обучения от процесса Mac не зависят.
