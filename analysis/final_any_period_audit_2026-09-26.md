## 3. Предложение: `src/run_final_any_period.sh`

### 3.1. Принцип

Почти все пути зашиты относительно корня (`data/prc-2026-datasets/ranking.parquet`, `submissions/…`,
`data/adsblol/…`). Поэтому сборка **не трогает `/root/prc-2026`**, а создаёт рабочий каталог
`/root/prc-final-<TAG>`: ссылки на `src`, `.venv`, `analysis`, `data/ext`, `data/cv_preds_nomonth`, обучающие файлы 2025 и
файлы ADS-B 2025 (по одному), а новый ranking/шаблон/METAR/ADS-B нового периода — настоящие файлы. Так снимаются сразу:
подмена ranking «не везде», подмешивание Jan/Jul в глобы `2026-*`, чужие `cat_reg_rank_seedN.npz`, `last_validation.json`.
Каждый шаг пропускается, если его выход уже есть (перезапуск после падения), и падает, если выход не появился; вывод
шагов идёт в `logs/<шаг>.log`, без `grep ^wrote`.

### 3.2. Параметры

| переменная | по умолчанию | смысл |
|---|---|---|
| `RANKING` | обязателен | новый ranking-файл |
| `SUBMITTING` | пусто | новый шаблон; если нет — строится из DEP-строк `RANKING` с типами старого шаблона |
| `TAG`, `WORK` | дата UTC, `/root/prc-final-$TAG` | рабочий каталог |
| `DAYS` | из `RANKING` (UTC-даты DEP) | дни ADS-B |
| `VB` | 900 | база: `vVB` (режимы), `vVB+1` (смесь) |
| `VT` | `VB+10` | хвост: `vVT+2…vVT+7`; другой `VT` = другой вариант хвоста на той же базе |
| `CAT_SEEDS` | 5 | 1 = состав v316, 5 = v366-семейство |
| `TABPFN_EXTRA`, `TABPFN_SEEDS`, `E136` | `pfx`, `0,1,2,3,4`, 0 | v316: `pfx`/`0`; v376: `pfx`/`0-4`; v386: `pfx,local_change`; v396: `E136=1` |
| `E81` | `drop` | `drop` — без смеси; `rebuild` — пересобрать v44/v60 на новых данных |
| `LOBT_LIFT` | 1 | 0 — только клип окна (`lobt_window_clip.py`) |
| `ADSB` | `download` | `skip` — без ADS-B (этапы E70/E64 пропускаются, E81 только `drop`) |
| `ADSB_ALLOW_MISSING` | 0 | 1 — продолжать при недоступных днях, помечая `data/final_any.degraded` |
| `WAIT_FOR` | пусто | список файлов-артефактов, которых ждать перед стартом (например, `data/e137.done`) |

Защитные проверки до счёта: схема нового ranking = схема старого (имена и типы; при отсутствии `AOBT_3_flt` нужен путь
NO_AOBT, разд. 21o); аэропорты ⊆ десяти; все дни в 2026 (иначе нужны правки глобов, см. ниже); `MVT_ID` не пересекаются с
2025; для `E81=rebuild` — наличие `data/adsblol/offblock{3,5}_2025-*` на hetzner (по памяти, там только `offblock2`).
После признаков — сверка схемы `features_e106` с эталоном `/root/prc-2026/data/features_e106.parquet` и совпадение
`airline_prefix`, `d_mvt_lobt`, `local_hour` на строках 2025 (так проверяется и нигде не записанная правка E106).

### 3.3. Что пересчитывать

Всё, что читает ranking: A4–A9 для новых дней, F1–F5 (+F6 при `rebuild`), M1–M11. Модели обучаются заново на 2025
(обучающая часть не меняется, но `train.py submit` учит и предсказывает одним вызовом — сохранённых моделей для
«только предсказать» у цепочки нет; `blend.py` умеет применять сохранённые `clf/reg`, а CatBoost и сиды — нет).
Не пересчитываются: файлы ADS-B 2025, `cv_preds_nomonth`, OSM, OpenFlights.

Время на hetzner (6 ядер): ADS-B ≈ 10–20 мин на день при 3 параллельных (скачивание ~3,5 ГБ/день + 11 проходов
экстракторов); признаки ≈ 0,5 ч; цепочка ≈ 4 ч; CatBoost 5 сидов ≈ +7 ч (4 × 1 ч 45 мин); TabPFN 5 сидов ≈ +0,5 ч;
