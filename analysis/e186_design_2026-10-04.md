# E186: TabM-style BatchEnsemble partner on FIN1b

Status: implementation and synthetic verification only. No PRC training may run before the
experiment code and its journal preregistration are committed together.

## Scientific contrast

E181b changed an ordinary MLP's width/epochs; E101 averaged independent networks. Neither
tested parameter sharing with separately initialized rank-one ensemble members. TabM remains
explicitly deferred in `REVIEW_BRIEF.md:336` and `:907`; journal rows 38/184 do not contain a
TabM run. E186 tests that missing mechanism, without claiming it can close the 13.6336-second
gap to third place. It is a custom **TabM-style BatchEnsemble**, not the official TabM package.

The regular candidate learns the same E181a target: ordinary regime only, clipped y in
[0,7200], minus the fold-fitted calibrated NM proxy, residual clipped to [-7200,7200] and
divided by its training standard deviation. Input is FIN1b with the exact E181a preprocessing:
fold target/residual encodings, training-only quantiles, rare categories mapped to zero,
`DROP_PREFIX=day_,tq_,wxr_,month`. **te_ and ter_ remain**, as in E181a. Existing preprocessing
uses quantile interpolation to [-2,2], not a Gaussian inverse CDF despite its old docstring.
`REGIME_RATES=0` is pinned before importing the preprocessing modules, matching E181a's absent
flag. Its value is recorded in both configuration and preprocessing-environment manifest;
an inherited `REGIME_RATES=1` cannot silently add regime-rate features.

The old shared category embeddings, hidden widths 512/512/256, SiLU, dropout 0.1 on the first
two hidden layers, AdamW lr .002/weight_decay 1e-5 and fixed eight-epoch OneCycle schedule stay.
Each hidden layer becomes W_j = diag(s_j) W diag(r_j), with k=16, independent first-layer
normal scales and independent heads. The loss averages **individual head MSE**, while
inference averages predictions. First-layer scale initialization shares one scale across
the coordinates of each categorical embedding. Logical batch4096 matches E181a; eight
microbatches512 accumulate gradients to preserve the number of optimizer updates.

## Feasibility and provenance

Execution target: **home-pc, AMD Radeon RX 7900 XTX, 24 GiB dedicated VRAM**,
Ubuntu 26.04, about30GiB system RAM. A separate `/home/a1/prc-2026/.venv-rocm` keeps the
existing CPU LightGBM environment intact. Root installed and verified **torch2.13.0+rocm10.0.0**,
HIP10.0.0, Python3.12; other packages match the Mac: numpy2.5.3, polars1.44.2,
lightgbm4.7.0, pandas3.0.5, pyarrow25.0.1, scikit-learn1.9.1, scipy1.18.1. Ollama was
stopped with user authorization; E185 ranking and OPDI ingestion may run concurrently.
This section records the root's live hardware/environment probe, not a PRC CV result.

`--device auto` chooses the visible CUDA/ROCm card with greatest VRAM, otherwise MPS.
The launch pins **`--device cuda:0`** after root verified that ordinal is the dedicated XTX.
An explicit unavailable or wrong device fails; CV forbids CPU fallback and `--device cpu`.
The standalone synthetic smoke supports CPU. MPS remains supported with `--device mps`.
All computation remains FP32, matmul precision highest, TF32 disabled, no mixed precision.
The architecture, seed0, eight epochs, batch4096, microbatch512 and inference batch4096
remain unchanged. Same seed does not imply identical random dropout streams across backends.

Default process peak RSS guard is **16GiB**, GPU allocator cap/guard **8GiB**, CPU threads**2**.
CLI overrides `--max-rss-gib`, `--max-device-gib`, `--cpu-threads` become part of the manifest.
Full features stay in CPU memory; only batches are copied to the selected accelerator.
Guards run before and after loading/preprocessing, during training/prediction, and at fold
cleanup. RSS is checked at phase/batch boundaries, not an OS-level hard limit; preprocessing
can transiently exceed the cap before its next guard, and torch's allocator limit does not
cap unrelated GPU processes. An out-of-memory/resource failure is operational, not a gate
result. Do not reduce width/epochs/microbatch or alter preprocessing after scored inspection.

Root's actual-architecture synthetic probe (272 numeric and14 categorical features,
k16, widths512/512/256, batch512) found CPU/GPU output max difference **3.7e-8** and
maximum gradient difference **3.7e-9**; median GPU step **3.6ms**, CPU4 **521ms**.
This is a compatibility/performance probe only; complete-fold memory and runtime remain
unmeasured. The previous Mac MPS probe was **51.46ms/step**, output max difference1.49e-8.
Six folds ×8epochs ×1.62Mrows /512 at3.6ms gives about9minutes of synthetic compute;
preprocessing, copies, gradient accumulation and concurrent jobs add runtime. Do not use
this extrapolation as a promised CV completion time.

Applicability is broad: any ranking row carrying regular/day probability can change, without
depending on ADS-B coverage; final protected tail rows cannot change. Actual affected ranking
counts and ideal *post-chain* headroom are not measured by this implementation. The generic
perfect-body oracle is not evidence for a TabM gain and is deliberately not used as its forecast.

Feature file, relevant source files, preprocessing environment settings and dependency versions
plus selected device/backend, GPU name/architecture/VRAM, host platform, torch/CUDA/HIP,
precision flags, CPU threads and memory caps are hashed into a resume manifest. Every fold requires exact unique ID set and target equality
to FIN1b OOF; all outputs carry manifest SHA and fold metadata. Different code/data/configuration
cannot be silently resumed. A different backend/device/software/hardware/cap also rejects
resume; use a fresh output directory for a genuinely new run. Completed folds are verified
before skipping; an incomplete fold is recomputed from seed0, never resumed from an epoch.
Do not merge folds from Mac MPS and home ROCm manifests. NPZ writes are atomic and one writer holds a per-output-directory lock.

If shared-weight ensembling is unhelpful, the strongest nearby untested alternative is learned
numerical feature embeddings (TabM's piecewise/periodic representations), as a separately
registered representation change. It is weaker priority than a demonstrated new observation,
and stronger than reopening the already rejected wider MLP or plain kNN without new evidence.

Primary sources checked 2026-10-04:
- [TabM paper, ICLR2025](https://arxiv.org/abs/2410.24210): parameter-efficient ensembles.
- [Official implementation/docs](https://github.com/yandex-research/tabm): independent-head loss,
  first-layer diversity, shared-weight regularization, k16 for exploration.
- [BatchEnsemble paper](https://arxiv.org/abs/2002.06715): rank-one modulation of shared matrices.
