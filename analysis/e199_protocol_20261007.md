# E199 — пространственное состояние других наземных транспондеров

Протокол `E199-other-ground-spatial-state-v-counts-retrospective-2pair-3seed-v1`.
Регистрация до любого target-fit; исходники `scripts/e199_airport_surface_state.py`.
Реальный вход — координаты одновременно наблюдавшихся других ICAO, а не интервалы
из AOBT/MVT и не остатки соседних рейсов. Это ограниченная проверка нового входа.

## Новизна и область применимости

E35/E60 использовали taxi-time соседей; H10 и E151 — интервальные counts/очередь
из часов; E183 — средние остатки/прокси. E192 использовал relations одинаковых
runway/stand и времени, без фактических координат. E197 относится к своему борту.
E199 измеряет концентрацию и близость других наблюдаемых наземных транспондеров.
Это не доказательство физической очереди, конфликтов или назначенного маршрута:
не исключены наземные машины с ICAO, ADS-B приём нерепрезентативен.

До регистрации выполнен только label-free probe на15января/15июля2025/2026:
2559/4676,3366/6120,3589/5001,4071/6180 строк имеют≥2 пригодных других объекта
хотя бы в одном снимке. Время1.05–1.63с/день наMac. Источник чисел:
`analysis/e199_coverage_probe_20261007.json`. Это четыре дня, не месячное покрытие.
LTFM почти не наблюдается; LIRF/LFPG неоднородны. Все427дней, все2429888ID
(2085047train+344841rank) извлекаются до проверки labels. Только31.12.2025
разрешён как известный отсутствующий raw-файл. Ранжирование используется только
для проверки доступности признака, без целевых значений/псевдометок.

## Точно фиксированные наблюдения

Использовать immutable E194 bundles/receipts регистрации
`fc7107de145a87a5a1ff93314f318b440b1de825`; helperSHA
`c2cf0a747f25de4219680799e1dac0a162007258908306f9670e9c3474c2e0eb`.
Сверять оригинальные rawSHA, sequenceSHA и departureSHA. Identity/airport/time/ID
должны точно совпадать с original departures; однозначный full-day callsign
identity E194. Неоднозначный/неизвестный ICAO => все context unavailable, fallback.
Фильтр собственного ICAO, включая его иной callsign/flight; не только MVT_ID.

Два снимка: MVT−600с и MVT−120с. В каждом аэропорту для каждого чужого ICAO
выбирать ПОСЛЕДНЮЮ запись t≤cutoff, разрешая равенство. При одинаковом t —
последнюю исходную строку. После выбора проверить возраст≤60с. Затем ground=true,
конечные допустимые lat/lon, stale!=true. Поэтому свежая airborne/stale запись
никогда не возвращает старую ground-позицию. Unknown stale допускается с явным
счётчиком unknown в ОБОИХ arms. Unknown speed не означает stopped; валидная
скорость0..100kt, stopped≤3kt, moving>3kt. Не делать интерполяцию/экстраполяцию.
Наблюдения суток не переносятся назад через полночь; если cutoff раньше
началасуток+60с, весь snapshot unavailable. Всё missing сохраняется как NaN,
availability отдельно. Ground0/нет данных не заменяются искусственными точками.

Full-day identity может использовать более поздний callsign. Поэтому это
**offline MVT-relative prediction** в рамках имеющихся конкурсных inputs,
не утверждение online causal forecast/идентификации только по прошлому.

## Сравнение признаков

Общие входы обоих arms: аэропорт, parent prediction,14existing FIN1b controls
(clock deltas,localhour,traffic/runway counts,plan_nm_taxi), safe-маски двух снимков.
Для каждого снимка одинаковые n_recent/n_ground/n_valid/stopped/moving,
unknownspeed/unknownstale/rejectedstale, mean/max age, mean/std speed,
knownheading и headingcoherence. Имеющиеся интервальные congestion входы
добавлены обоим: геометрия обязана принести сигнал сверх них.

Только spatial-arm получает11полей на снимок: occupiedcells250/500м,
maxcell250/500, HHI250/500, RMSрадиус относительно центроида, доли пар ближе
250/500м, средний nearest-neighbor между stopped, доля stopped-пар<250м.
Локальные метры относительно фиксированной аэропортовой точки E194.
Фиксированная grid origin аэропорта; никакого обучения зон по labels.
Дистанции считаются блоками128×N, без полногоN² массива или отбора удобных бортов.
Если меньше2пригодных точек — вся геометрия unknown. Headingcoherence общая,
чтобы прирост spatial не подменялся новым распределением направлений.

Eligibility для обучения/применения: unique ownidentity и≥2validothers хотя бы
в ОДНОМ из двух снимков плюс parent evaluation_mask=true. В остальных строках
оба arms точно возвращают parent. 126TabPFN и parent-feasibility exclusions
сохраняются. Весь ranking извлечён, но модель на нём в этом протоколе не обучается.

## Фиксированный CPU screen

Parent — immutable E195 `data/e195_pre_e81_20261007_v2/predictions.parquet`,
arm `joint`, resultSHA `94ba00d1522b7d598bc9d3b42d3361ad68af9dd41ca19b120c5c07f023e05f9e`.
FIN1b SHA `f061a441f6c97c232d9a403d612471e45020eb4ad56f501c2acfd7220a7d3052`.
Обучаем additive residual y−parent без клиппинга residual/отбора по y.
Только observable eligibility; target нигде не входит в features.
Пары1+7 и4+10; другие10месяцев train для каждой пары. Counts и spatial получают
точно одинаковые строки, параметры, seed и sharedinputs. В counts spatialcolumns
константнонулевые; одинаковая ширина input и treebudget, не обещание одинаковых
выученных деревьев. По3seed42/1/2,300trees,31leaves,minleaf500,lr.05,L2=10,
feature_fraction1,bagging.8/freq1,max_bin255,deterministic/force_col_wise.
Всего12fit, без earlystopping/подбора. Airport categorical; NaN обрабатывает LGB.
Среднее трёх corrections добавляется к parent с фиксированным весом1,
итог clip≥0. Ни shrinkagegrid, ни отдельной настройки airport/window нет.

До fit требуется фиксированная availability-admission:≥10000eligible в КАЖДОМ
из Jan25/Jul25/Jan26/Jul26. Это guard покрытия/переносимости, не RMSEпорог.
Сохранить полноценную month×airport coverage для оценки дрейфа.
При fail — завершить extraction и отчёт, не fit, без поиска другого порога.

Primary spatial должен улучшить ОБА контроля: freshcounts И unchangedjoint.
В КАЖДОЙ из двух пар deltaSSE<0 для body(y≤7200),decided,trim3,trim20.
Decided исключает LIRF/noNM/d_mvt_sched≥14400; дополнительные126parent exclusions
одинаковы. Trim удаляет3/20 наименьших и наибольших paired deltaSSE, как ранее.
All-RMSE, отдельноJan/Jul/Apr/Oct, perairport и seedvariability — диагностика,
не разрешение выбрать выигрышный карман. Не менять gates после результата.
При fail конфигурацию не масштабировать. При strict screen PASS автоматически
выполнить оставшиеся пары2+8/3+9/5+11/6+12 тем же рецептом: ещё24fit, безтюнинга.
Для запуска нужны verified screen receipt, тот же inputmanifestSHA/registration.
Это отдельные четыре confirmationпары; исходные две явно selected screen.
Итоговый sixpair gate против ОБОИХ controls: decided лучше≥4/6пар, сумма bodySSE,
trim3SSE,trim20SSE<0. Не интерпретировать слабый хвостовой выигрыш как успех body.
Даже после sixpair PASS нужен новый registered base-member/nested confirmation;
автоматической подачи/fullranking здесь нет.

**Ограничение:** train-residuals взяты из исторических OOF разныхfold. Собственные
heldoutlabels stage не видит, но upstream parent другихfold мог зависеть от них.
Это retrospective input screen, не independent nestedCV/fullproduction-chain.
Parent заканчивается доE81/окончательныхtail/LSZH; не называть его fullchain.
Экспертный prior Δbody spatial−counts:0с; некалиброванный диапазон[−1,+1]с,
не доверительный интервал/обещание/порог. Прогноздоски не формируется.
