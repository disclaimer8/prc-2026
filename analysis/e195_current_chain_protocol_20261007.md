# E195 — ретроспективное сравнение текущей цепочки: этап 1

Протокол: `E195-current-chain-retrospective-stage-models-six-pair-v1-20261007`.
Код: `scripts/e195_current_chain.py`. Требуется единый коммит кода и строки журнала
до любых реальных fit. Этап 1 готовит неизменяемые данные и модели корректировщиков;
он **не выдаёт полный CV, итоговые прогнозы, оценку качества или разрешение подачи**.
Полная сборка четырёх фиксированных плеч остаётся обязательным следующим этапом.

Сравнение предназначено для control / E190 / E188 / E190+E188 при исходных весах
производства, без выбора по уже известным оценкам. Готовые CatBoost15 OOF из
`data/cat_extra175_20261006/merged`, LightGBM5, обычный MLP3, E190 PLE3 и якоря
повторно не обучаются. Их смешивание и все последующие операции будут отдельно
зарегистрированы после проверки полного происхождения старых доноров E81 и
кэшированных TabPFN-аналогов. `cv_preds_e38` / `cv_preds_e46` нельзя молча объявлять
полными аналогами v44 / v60: в ranking эти файлы прошли дополнительные этапы.

## Зафиксированные модели

Для каждой наружной пары `(1,7)…(6,12)` обучаются независимо:

| Модель | Исторический родитель и строки | Признаки | Деревья / сиды |
|---|---|---|---|
| E141/E169 | `cv_preds_e116prod`, coverage≥2, keep-all | исходные E141, исключён D7 | 800 × 42,1,2,3,4 |
| E64 | `cv_preds_nomonth`, coverage<2, предыдущий визит | исходный D3, 11 признаков | 400 × 42,1,2,3,4 |
| E188 | тот же nomonth, естественные строки + синтетические копии | те же 11, вес синтетики 0.25 | 400 × 42,1,2,3,4 |
| LSZH E159b/c | старый `cv_preds_e150c_e64_keep`, все месяцы LSZH с OPDI exit | d_opdi,t_opdi,pred,twy_s | 300 × 42 |

У E141/E64/E188 residual `y−base` обрезается в ±1800 секунд; у LSZH остаётся исходным.
Все LightGBM параметры берутся из замороженных производственных исходников; только
число потоков задаётся ресурсным профилем машины. У LSZH — точные исходные параметры
E159b: leaves15, lr0.05, minleaf100, L2=10, bagging0.8/freq1, deterministic.
Все модели пары обучаются только на остальных десяти месяцах; собственные метки
наружной пары не входят в fit. Полных fit: **96** (16 на каждую пару). Early stopping,
подбора параметров, смены сидов и автоматического частичного среднего нет.

E188 сохраняет исходную популяцию зарегистрированного успешного screen: 318697
естественных строк и 60327 наблюдаемо допустимых синтетических, вес последних0.25.
Синтетика только в train; `month` исходного рейса определяет исключение наружного
фолда. Файл признаков естественных рейсов сохраняется для последующего применения;
генерировать синтетические ranking/validation строки этот этап не будет.

## Происхождение и границы

E141/E64 используют ровно замороженные формулы из
`data/today_chain_source_20261006/src`: исполняются только явно выбранные AST
константы и определения функций. Исторические import-side-effect CV не вызываются.
Сенсоры: `adsblol_kt1` offblock2/3/5, `adsblol_sw_kt1` offblock2, исходные
`adsblol` visit/visit_m/head за2025. На каждый тип364 файла; 31 декабря сохраняется
с отсутствующими сенсорами. Уникальность всех 2085047 исходных departure ID проверяется.

E188 читает только фиксированные manifest/extraction v2 и сверяет каждую из365
дневных проекций. LSZH читает **ровно44 старых OPDI файла из зафиксированного
`e159_fixed_lineage.json`**, без подмешивания свежего glob; полный исторический
набор содержит84758 строк. Сохраняются сопоставления OPDI для последующей сборки.

Входной manifest содержит SHA исходных файлов, замороженных функций, готовых
матриц и самого worker. Файлы входов проверяются повторно перед атомарной
публикацией пакета. Worker запускается из копии внутри пакета, проверяет все SHA
до/после fit, сохраняет каждый модельный файл и сведения о train/heldout популяции.
Неоконченный каталог скрытый; готовый публикуется только после всех16 моделей пары.
Существующие каталоги не перезаписываются, автоматического resume/retry нет.

Это **ретроспективное сравнение с историческими upstream OOF**, а не независимо
вложенный CV: другие OOF upstream могли обучаться на метках текущей наружной пары.
Исключение пары из нового stage-fit эту зависимость не устраняет. Ограничение
описано в `analysis/codex_deep_audit_validation_2026-10-04.md:57` и должно сохраняться
во всех последующих отчётах. Этот этап ничего не утверждает о её величине.

## Запуск и обязательное продолжение

Mac готовит пакет существующим `.venv/bin/python`, без Torch, uv и изменений сред.
Mac получает пары1,2 /8потоков; Home пары3,4 /12потоков, MemoryMax16G/Swap0;
Hetzner пары5,6 /6потоков и `taskset -c 0,2,4,6,8,10 nice -n 10`.
На каждом host пары выполняются последовательно; Home GPU-задача сохраняет свои
2CPU/12G. Запущенные GPU/CI/чужие сервисы не изменяются. Полный пакет один на host.

После регистрации REG:

```sh
.venv/bin/python scripts/e195_current_chain.py pack --root . --output data/e195_stage_inputs_20261007 --registration-commit REG
.venv/bin/python data/e195_stage_inputs_20261007/scripts/e195_current_chain.py fit --input data/e195_stage_inputs_20261007 --output data/e195_stage_models_20261007/fold_1_7 --host mac --fold 1 --registration-commit REG
```

Пока модели считаются, следующий зарегистрированный этап обязан восстановить
исходные Cat15/.65 + LGB5, все фиксированные якоря/MLP веса, E185 subset,
E167 probabilities/LOBT, допустимый кэш TabPFN, arm-specific base-зависимые признаки
E141/E64/E188, E152.95, точный E81 (.8516/.1214/.0270), LOBT lift/clip, защиту доноров
и половинный LSZH. При недостающем кэше/доноре итоговая полная сборка остаётся
неполной; подмена приближением требует явного отдельного названия и регистрации.
Нельзя завершить работу одним stage-screen или назвать его полным current-chain CV.
