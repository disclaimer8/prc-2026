# Ревью решения gentle-igloo (PRC 2026, состояние 13.09)

## 1. Итог в 5 строк

1. **Критично:** классификатор режимов слеп на хвосте. LIRF без записи NM при D = MVT−SCHED > 8 ч: в 2025 году 100 % (21/21) строк = «sched» при 8–12 ч и 61 %/39 % «sched»/«сутки» (17/11) при 12–30 ч; модель v6 даёт p_sched = 0,63 и p_day = 0,0002. Замена на таблицу с leave-Jan/Jul-out убирает **33 % SSE валидации** (390,3 → ≈319). В ranking таких строк 21 (8–30 ч), экспозиция на месяц вдвое выше, чем в 2025.
2. **Критично:** разметка `TOL=30` с ложна: сигнал «block = sched» — это полоса ±6 с и только в 7 аэропортах; в EDDF/EHAM/LSZH его нет вообще. ~24,5 тыс. из 113 тыс. меток «sched» — обычные рейсы (98,5 % всех «sched»-меток имеют y ≤ 3600).
3. **Важно (баг):** `taxiing_at_ob` — накопительный счётчик, дрейфующий по календарю: медиана −63 (янв 2025) → −1873 (дек 2025) → −2231 (июль 2026). Это скрытая абсолютная метка времени.
4. **Важно:** 1,6 % строк без NM дают 67 % SSE валидации (LIRF 44 %, LFPG 20 %); отдельной модели для них нет. Оракул по режимам дал бы RMSE 280 вместо 390 — резерв в классификаторе, а не в регрессоре.
5. **Возможности:** таблица режимов LIRF (1 день, −30…−70 с на LB по моей оценке), чистые метки + специалист без NM, гейт прокси по |AOBT−LOBT| > 3606, честные фолды по парам месяцев. Утечек block time нет, `_window_stats` и соседи проверены брутфорсом (0 расхождений на 300 строках).

## 2. Находки

### Критично

**К1. Классы «сутки» и «sched при D > 8 ч» не выучиваются классификатором.**
- Доказательство: `src/train.py:68` — `CLF_PARAMS ... min_data_in_leaf=100`; строк класса dayshift в 2025 году 14 (моя проверка c1), бин LIRF/no-NM/8–12 ч — 21 строка. Лист из 14 строк невозможен. В `submissions/parts_v6.npz` сумма p_day по всем 344 841 строкам ranking = 0,04, ни одной строки с p_day > 0,1 (c7).
- Таблица LIRF без NM по бинам D (c14, весь 2025): <2 ч — other 535 / sched 325 / day 0; 2–4 ч — 203/296/1; 4–8 ч — 15/62/0; 8–12 ч — 0/21/0; 12–30 ч — 0/17/11. При D ≥ 8 ч «прочих» строк нет вовсе.
- Эксперимент: вероятности из 10 fit-месяцев, применение к Jan+Jul 2025 (leave-out): бин 12–30 ч — SSE 1,81e10 → 1,82e9 (**−31,1 % всего SSE валидации**), 8–12 ч — 5,1e8 → 27 (−1,0 %), 4–8 ч — 1,51e9 → 1,0e9 (−1,0 %). Итого −33 % SSE → RMSE ≈ 319.
- В ranking (c14): LIRF/no-NM: 4–8 ч 21 строка, 8–12 ч 11, 12–30 ч 10; v6 даёт там p_sched 0,53/0,63/0,63, p_day ≈ 0. На 2025 те же бины дают 8,2 / ~1,8 / 2,3 строки в месяц, т.е. экспозиция ranking в ~2 раза выше.
- Оценка эффекта на LB (моя арифметика на 10 строках 12–30 ч и P(day)=0,35): экономия ≈1,5e9 SE на строку → ~45 000 к MSE → 339 → ~265. Даже при P(day)=0,2 выигрыш десятки секунд. Один пропущенный «суточный» ряд стоит +30 с (86400²/344841 = 21 650 к MSE при 339² — совпадает с оценкой брифа «~34 с»).
- Исправление: иерархия «правила → модель». Для (LIRF, нет NM) — сглаженная таблица P(sched), P(day), P(other) по бинам D (Лаплас/бета-априор), кандидаты: D, 86400 + медиана такси (768–1992 по 14 строкам, медиана ~1000), регрессор. Для остальных строк оставить LightGBM. Альтернатива — снизить `min_data_in_leaf` для клf и добавить веса классов, но при n=14 таблица надёжнее.

**К2. Допуск 30 с в `regime_label` размечает обычные рейсы как режим.**
- `src/train.py:31` (`TOL = 30`), `:98-104`. Гистограмма BLOCK−SCHED по секундам (c6, весь 2025): плато ≈8000/с на [−6, +5], фон ≈340/с вне него. По аэропортам (|bs|=0 / 1–5 / 6–30 с): EDDF 133/1336/6675, EHAM 161/1514/7042, LSZH 69/803/3130 — спайка нет, это фон (у них секундная разрешающая способность: :00 у 1,7 % меток). У остальных семи спайк есть (LIRF 2429/24167/2494).
- Итог TOL=30: «sched» 113 446 меток, из них 111 768 с y ≤ 3600; полоса 6–30 с даёт 24 542 ложных «sched» (16 847 в EDDF/EHAM/LSZH); аналогично IOBT 24 421, EOBT 36 958. Всего из регрессора выброшено 8,4 % строк, смещённых в сторону пунктуальных (регрессор недооценивает на −35 с строки с |bs| 31–300 с, c6).
- Спайк-строки против фона: y > 3600 — 1,04 % против 0,08 %; |AOBT−BLOCK| ≤ 90 с — 27 % против 31 %. Это действительно подмена, но ±6 с, а не ±30.
- Исправление: TOL = 6 с; в EDDF/EHAM/LSZH классы sched/iobt/lobt/eobt не размечать (только dayshift). Затем переобучить clf и TE (TE считается по regular-строкам, `src/target_encoding.py:57`).

### Важно

**В1. `taxiing_at_ob` — накопительный дрейф вдоль ленты времени.**
