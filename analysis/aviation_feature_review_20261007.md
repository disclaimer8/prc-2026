# Пять авиационных гипотез — сверка с текущей моделью, 7 октября 2026

Проверены схема локального ranking, FIN1b, `src/features.py`, текущий список
признаков, журнал и бриф. Это проверка доступности и новизны. Новых RMSE или
оценок эффекта здесь нет; старые числа относятся к своим старым контролям.

## 1. ATOT, AOBT и TSAT

Предположение «в тесте не должно быть ATOT» не соответствует этому конкурсу.
Официальное [описание данных](https://prc-data-challenge-2026.netlify.app/data.html)
оставляет время движения и скрывает departure `BLOCK_TIME_UTC_mvt` и
`TAXITIME_SEC_mvt`. Это реконструкция записанного интервала, а не прогноз до
pushback. В локальном ranking 344841 вылет: у всех есть `MVT_TIME_UTC_mvt`, у
всех скрыты оба целевых поля. `AOBT_3_flt` отсутствует только у5290 вылетов;
это отдельная NM-запись, не скрытое airport block time. TSAT среди30 входных
колонок нет. Разности с AOBT/LOBT/IOBT/EOBT/SCHED уже используются.

Решение: не удалять разрешённый take-off/AOBT_3 и не объявлять их утечкой по
названию. В документации явно описать временную границу задачи; отдельно
проверять реальную зависимость от скрытых departure block/target и fold leakage.

## 2. Смена конфигурации ВПП

Уже есть `RUNWAY_mvt`, `ap_runway`, `n_dep_rwys`, `n_arr_rwys`,
`own_rwy_share_hour`, интервалы между движениями и runway congestion. Строковая
`rwy_config` строится, но исключена production `DROP_PREFIX`; нельзя говорить,
что весь её смысл полностью отсутствует или полностью учтён.

Прямого `minutes_since_runway_config_change` в FIN1b нет. Это содержательное
дополнение для дешёвой диагностики: устойчивый переход набора используемых
ВПП, а не смена полосы у двух соседних рейсов на многополосном аэродроме.
План будущей конфигурации не найден; нельзя назвать наблюдаемую будущую смену
«известным планом». Для этого retrospective конкурса время до наблюдаемого
перехода можно изучать отдельно, с явным описанием доступной информации.

Параллельный разбор уже записал в журнале №357 грубую проверку: большинство
направления последних10вылетов, перенос поправок между полугодиями. Она
ухудшила MSE на36с²/строку. В EDDF получилось около47тысяч «переключений»,
поэтому это проверка шумного индикатора, а не надёжно восстановленного режима.
Источник результата — запись №357 и `scratchpad/paste1316_probe.py`; здесь
он повторно не вычислялся. Не повторять эту пробу и не объявлять всю идею
устойчивых переходов исчерпанной. Новое обучение сейчас не назначено.

## 3. De-icing

Почти предложенный флаг уже есть: `wx_icing = temp<=3 AND
(temp-dewpoint<=3 OR snow OR freezing)`, плюс `wx_icing_recent`, снег/осадки.
Это индикатор условий, а не вероятность фактической обработки, равная1.
Температура/влажность сами по себе не доказывают маршрут через площадку и время
обработки конкретного борта.

Поздний OSM-обход в брифе уже исправляет раннее «ничего нет»: найдены именованные
площадки LSZH2, LTFM5 и точка EDDM; структурных deicing-тегов и покрытия всех
аэродромов не было. Это исторический снимок OSM, не доказательство текущего
отсутствия площадок. Старое число0.095с относится к снятию среднего смещения
холодных LTFM-строк; оно не является потолком любой модели de-icing.

Решение: не повторять погодный флаг. Новая механика потребует наблюдения
посещения площадки/очереди или проверенной геометрии и покрытия, которых эта
гипотеза пока не предоставляет.

## 4. Грозы и CB: найдена конкретная неполнота парсинга

`wx_thunder` уже строится по `wxcodes.str.contains("TS|CB")`. Однако CB может
быть в облачной группе сырого METAR, не в поле `wxcodes`. Архив содержит сырой
текст. В проверенных локальных сводках2025–2026 найдено5593 записи с облачной
группой `FEW/SCT/BKN/OVC` + высота + `CB`; у4608 из них текущий флаг по wxcodes
не срабатывает. Это число сводок, не рейсов и не доказанный выигрыш.
Из них2880пропусков относятся к2025году,452—именно кянварю/июлю2026.
Остальные относятся кдругим датам локального архива. Подсчёт воспроизводится
через `scripts/metar_cb_inventory.py`; входныеSHA и разбивка сохранены в
`analysis/metar_cb_inventory_20261007.json`. Возможные исходные дубли сводок
не удалялись; связывание с рейсами ещё не выполнено.

| Аэропорт | CB в облачной группе | Без текущего TS/CB-флага |
|---|---:|---:|
| EDDF | 261 | 249 |
| EDDM | 348 | 328 |
| EGLL | 125 | 111 |
| EHAM | 2017 | 1959 |
| LEBL | 673 | 429 |
| LEMD | 631 | 371 |
| LFPG | 623 | 570 |
| LIRF | 217 | 123 |
| LSZH | 411 | 266 |
| LTFM | 287 | 202 |

Решение: отдельный CB-признак из уже имеющегося сырого METAR заслуживает
проверки покрытия рейсов и добавочного сигнала. До неё production-парсер не
менять. История погоды E193 уже дала отрицательный результат, но это не та же
проверка. Старое снятие среднего грозового смещения0.001с не ограничивает
возможные взаимодействия и не покрывает пропущенный CB.

`nearest_storm_distance` не получается из одного аэропортового METAR.
Нужен пространственный архив нужного периода. [Blitzortung](https://www.blitzortung.org/en/cover_your_area.php)
предоставляет raw data участникам сети с некоммерческим использованием; считать
его автоматически общедоступным архивом под открытой лицензией нельзя.
Сейчас новый такой источник не принят.

## 5. Группы типов самолётов

В модели уже есть ICAO aircraft type и `WK_TBL_CAT_flt`. У ranking5304 вылетов
нет NM wake category. Engine count/ICAO size code как самостоятельные признаки
не найдены. Утверждение «около10 групп всегда лучше50 типов» не проверено и
может потерять различия frequent types.

Параллельная запись №357 сообщает406rankingвылетов с новым типом и860с типом,
редким в2025(≤100вылетов). Указанное там0.07с — оценка конкретного исправления
ошибки выбранной малой группы, не теорема о пользе всех физических признаков.
Решение: если возвращаться к идее, сохранять исходный тип, добавлять
физические группы и missing/unknown отдельно; оценивать на редких/новых типах
при том же временном разрезе. Замена всех категорий заранее не обоснована.

## Приоритет

E202→E203 и воспроизводимость остаются первыми. Конкретный новый пробел —
пропущенные облачные CB-группы. Устойчивая конфигурация ВПП пока не восстановлена;
её грубая замена уже проверена отрицательно. Обещания секунд до проверки не даются.
