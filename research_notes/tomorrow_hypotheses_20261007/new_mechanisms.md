# Новые механизмы для 7 октября: что имеет смысл поставить на ночь

Подробный отдельный разбор всех пользовательских предложений (TGN/TGAT/DySAT, PINN, multimodal, causal, diffusion, RL и digital twin), с уточнённым matched-input graph протоколом: [user_hypotheses_review.md](user_hypotheses_review.md). Это исследовательские предложения, а не результаты fit. Точная схема raw ranking и новый замер присутствия METAR: [verified_inputs.json](verified_inputs.json).

## 1. Контекст из отдельных движений аэропорта вместо сжатых счётчиков

### Takeaway

**Первый приоритет для новой пробы — модель, которая видит последовательность конкретных соседних движений и выбирает их относительно своего рейса.** Она достигает почти всего ranking, включая слепой для ADS-B Стамбул. Это новая форма входа; выигрыш пока не измерен. Рекомендую один небольшой парный screen сегодня, затем продолжение только по его результату. Не требуется ждать Cat90: для скрина достаточно готовой базы E182+E185/контроля E190, с честной пометкой pre-ADS-B/LGB5-only там, где это действительно так.

Приоритет после чтения кода: **событийный контекст → полная последовательность своего борта → совместная вероятностная модель записанного времени**. Первоначально наиболее удобной казалась третья линия, но замер неоднозначных часов сам по себе её не обосновывает: близкие плановые кандидаты часто дают практически один прогноз, а E107 уже проверял их перераспределение.

### Inferences

**Механизм и отличие от закрытого.** Два окна с одинаковыми счётчиками и средними могут иметь разный порядок пересечений ВПП, разный состав бортов по маршрутам/стоянкам и разные зависимости между отходом и взлётом. Модель получает не ещё один средний остаток, а отдельные наблюдаемые события. Query-conditioned attention может выбрать именно соседей, связанных с текущей ВПП/стоянкой/временем. Низкая корреляция среднего остатка E183 не является верхней границей такого взаимодействия; это, однако, лишь логическое различие, а не свидетельство ненулевого эффекта.

**Ровно один первый протокол, без перебора архитектур.**

1. Для каждого движения определить аэропорт наблюдения: DEP→ADEP, ARR→ADES. Построить индексы по `(airport, MVT_TIME)`. Для запроса взять до32 предшествующих и32 последующих событий в ±3600с, себя удалить поMVT_ID; недостаток заполнить PAD. Ничего не подбирать поy. Последующее наблюдаемое движение разрешено условиями retrospective ranking так же, как существующие `dep_after_*`; не называть это прогнозом в реальном времени.
2. Токен: относительное MVT-время, фаза, ВПП, префикс стоянки, тип/турбулентность борта, оператор, разности MVT−AOBT/LOBT/SCHED, признаки отсутствия и равенства своей ВПП/стоянке/оператору. **Во всех departure-токенах запретить `BLOCK_TIME_UTC_mvt`, `TAXITIME_SEC_mvt` и все производные.** Для первого screen проще вообще исключить BLOCK/TAXI и уARR: тогда невозможна путаница масок. Месячный номер/абсолютныйID не подавать; ID — только для индексации.
3. Query — обычный FIN1b/PLE-вход, как E190. Encoder контекста:64мерных токена, два слоя cross-attention с4головами и feed-forward128; pooled context добавляется к query encoder. Позиция — относительные времена, не абсолютная дата. Предсказывать тот же обычный кандидат `(y−proxy)/sd` на той же `regime_label==0` популяции, что E190. В токенах не использовать прогнозы/остатки иных моделей: это убирает дополнительный nested-OOF риск и делает именно наблюдаемый вход единственным изменением.
4. **Парный контроль:** такой же query encoder без реального контекста; второй контрольный прогон или дешёвый ablation — контекст из другого дня того же аэропорта, сопоставленный безy. Не приписывать архитектуре новых данных выигрыш, который сохраняется с чужим днём.
5. Фиксированные outer-пары **1+7 и4+10**, seed0,8эпох, без early stopping по оцениваемым месяцам. Все target-encodings/нормировки обучать только на outer-fit. На inference в свою обучающую часть не подмешивать метки соседа из отложенного месяца. Контекст содержит только наблюдаемые входы, поэтому календарное соседство само по себе не является утечкой.
6. Новые прогнозы поставить на место MLP-компонента с его уже фиксированным коэффициентом, без подбора веса по результатам. Сначала сравнить с **matched query-only** и с текущим готовым контролем. Посчитать decided,body≤7200,trim, отдельноNM-LTFM и по месяцам, bootstrap целыми airport-days. Для продолжения body иtrim должны быть ниже в обеих outer-парах, а выигрыш не должен исчезать после удаления локальных лучших/худших20 изменений SSE. Если весь выигрыш только в хвосте или только против ослабленного query-only контроля, линию не расширять.

**Рunnable outline для исполнителя.** Отдельный `scripts/<new_id>_event_context.py` с `pack`, `fit`, `evaluate`, `rank`; immutable каталогиinputs/outputs. `pack` читает `features_fin1b.parquet` и исходные `training_*.parquet`/`ranking.parquet`; сохраняет компактные таблицы токенов и int32индексы `[N,64]`, а не размножает весь контекст. `fit` использует существующие `scripts/mlp_lowmem_prepare.py`, PLE-фабрику из `scripts/e190_numeric_embeddings.py` и изолированнуюROCм-среду, не меняя их исходники. `evaluate` собирает новую копию кандидата через существующую формулуregular/mix; изменение количества сидов/составабоевой смеси не нужно. Если2пары проходят,6пар×1seed для проверки устойчивости и отдельныйfulltrain→ranking. Полный файл с новым компонентом оценивается как новая гипотеза, а не как подбор весов сегодняшних файлов.

**Бюджет ночи, оценка до бенчмарка.** Упаковка исходных движений:0,3–1,5ч на6CPU, затем четыре fit для двухпар×двухплеч:ориентир0,5–2чGPU. Реальная скорость контекстной модели не измерена; после200batchs экстраполировать фактическое время и остановить расширение, если полныйночной план не укладывается. Токены хранить один раз, индексы2,4млн×64int32≈615MB; floatcontext раздувать только вbatch. ОграничитьCPU preprocessingдвумя потоками при соседнемCat. Не обещать «пару секунд» до результата.

### Gaps

- **Информативность не измерена.** Большой LTFM SSE и богатый контекст — необходимое поле применения, не прогноз улучшения. E151/E157/E183 могли уже сжать почти всю полезную информацию.
- Новый наблюдаемый источник отсутствует; это более полное представление уже выданных данных. Если требуется именно новая внешняя таблица с правильной лицензией и покрытием2025/Jan+Jul2026, такой таблицы этим исследованием не найдено.
- Наблюдения после takeoff доступны в файле конкурса; реальный deployment доотхода потребовал бы другой постановки. Для наших submissionусловий нужно сохранить ровно текущую трактовку доступности из `features.py`.
