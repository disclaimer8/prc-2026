## 2. E168 — пред-регистрация: этап OPDI на объединении наземных событий

**Что.** Популяция этапа = строки с любым из `exit-parking_position` / `exit-apron` / `entry-taxiway`
(EDDF + LSZH, 2026). Признаки: время каждого из трёх событий отдельно (не только якорь), индикатор
«какое событие есть», существующие `d_opdi`, `t_opdi`, `twy`, `base`. Обучение — LSZH 2025, LOMO по
12 месяцам (протокол E159c), для EDDF — тот же сдвиг `airport_offsets` (+139 с, журнал №173).

**Ворота.** Как E159c: RMSE ниже цепочки в ≥ 10 из 12 месяцев, отдельно для строк с нашим покрытием и без;
усечённые < 0. Отдельно смотреть подмножество «только entry-taxiway, без exit-parking» — если там
выигрыша нет, расширение популяции не брать (оставить только `exit-apron` как признак).

**Прогноз (записан до прогона).** По формуле журнала №177 (строки × ΔRMSE² / 344 841):
- LSZH, +3 982 строки при том же выигрыше (153,5² − 94,3²): ≈ 169 с² MSE → **−0,36 с**;
- LSZH, `exit-apron` как более точный якорь на уже покрытых 14 155 строках (94,3 → 85 с): ≈ 68 с² → **−0,15 с**;
- EDDF, +11 850 строк: при −20 % RMSE ≈ 283 с² → **−0,60 с**; при −10 % → **−0,32 с**; при 0 — ноль
  (события в EDDF шумнее: in180 = 9,3 % у entry-taxiway против 23,9 % у exit-parking).
- **Итого сверх v729/v719: −0,5…−1,1 с**, центр −0,7.

**Два файла, как v729/v719:** LSZH-only и LSZH+EDDF — потому что EDDF-2025 проверить нельзя
(OPDI там в 2025 мусор: покрытие 3 %, медиана +589 с), перенос обоснован только совпадением
`OPDI − t_first ≈ 0` в 2026 (№173).

**Стоимость.** CV — минуты (данные локальны, `data/opdi/ev_*`); сборка — хвост `e159b_apply.py` с новым
набором событий, ~1 ч. **Слоты 2.10** (1.10 заняты: v655, v729, v719, v695, v665).

**Риск.** На EDDF entry-taxiway может добавить шум; поэтому два файла и гейт на подмножестве «только
entry-taxiway». Лицензия закрыта разрешением организатора 06.09 (№168).
